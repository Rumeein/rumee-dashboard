Rumee — Amazon Tab

Five reports, filling in as they arrive

LIVE
2026-07-24

Amazon is the newest platform integration, built on SP-API's Reports API -- a request-then-poll flow, not an instant call. Five separate report types feed five separate sections of this tab, each one loading independently and filling in the moment its own data resolves.

the pipeline / the tab itself
01

Request, then poll -- not an instant call

SP-API's Reports API is stateful: process.py requests a report, then polls until Amazon says it's ready, for each of five report types every run. This is fundamentally different from Flipkart/Meesho's file-export model, and it's why Amazon data can occasionally lag a bit behind the other two platforms within the same pipeline run.

02

Five collections, five independent loaders

Opening the Amazon tab renders instantly from whatever's already cached, then fires all five loaders in parallel -- Orders, Returns, Keywords, Settlement, Catalog. Each one re-renders the tab the moment its OWN fetch resolves, so a slow settlement fetch never blocks the orders section from showing up first.

03

Every section says exactly where its data came from

Each of the five detail sections shows a "Source: rumee_az_…" caption -- Jaiswal's explicit ask for traceability, so if a number ever looks wrong, you already know which Firestore collection (and therefore which SP-API report) to check first.

04

The monthly rollup is a separate, cheaper path

KPI cards and the monthly trend chart don't wait on any of the five tab-open loaders -- they come from rumee_az_daily, a monthly rollup already derived from order data during the pipeline run (no extra live API call), loaded the same way Master's monthly summary is.

Worth knowing

The Amazon LWA client secret needs manual rotation on a schedule -- the tab shows its own rotation-window banner as a reminder, since this is one of the few genuinely manual dependencies left in an otherwise fully automated pipeline.

Not yet built

Ad spend for Amazon is not yet wired in -- the "SP-API Status" card on this tab explicitly lists it as "pending Amazon Advertising API integration," not a silent gap.
