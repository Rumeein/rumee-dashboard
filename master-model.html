Rumee — Master Tab

Three platforms, one number

LIVE
2026-07-24

Master is the cockpit view — Flipkart, Meesho, and Amazon rolled into one set of KPIs and charts, so you can see total orders, GMV, settlement, and returns without flipping between three platform tabs. It renders in two passes: an instant monthly-grain view, quietly upgraded to daily-accurate numbers a moment later.

the shared daily pipeline / the tab itself what you actually see
01

One pipeline, three platforms

process.py runs once a day via GitHub Actions and processes Flipkart, Meesho, and Amazon data in the same run -- there's no separate per-platform pipeline. It writes two different shapes of data to Firestore: a single monthly-grain summary blob, and separate daily-grain documents, one per month, per platform.

02

Two Firestore layers, two different jobs

rumee_db/summary holds monthly totals for every platform (GMV, orders, settlement, returns, ad spend) inside one CSV blob stored in a single Firestore field -- cheap to fetch, always available. Separately, rumee_fk_daily/rumee_me_daily/rumee_az_orders_daily (and several siblings) hold real day-by-day rows, one Firestore document per calendar month, fetched only for the last few months at a time.

03

The tab renders twice, on purpose

loadSummary() fetches the monthly blob first and paints KPIs/charts immediately -- you're never staring at a blank screen. In the background, loadDailyData() pulls the last 3 months of daily documents across 8 collections in parallel, and once that resolves, everything re-renders with real period-over-period comparisons (this week vs last week, not just "this month's total").

04

All-time is separate, and never loads unless asked

A dedicated "Load All-Time Data" button reads rumee_db/alltime -- full daily history since the very first sale. This never loads automatically (it would be wasteful for a daily check-in), and it's stored completely separately from the rolling 3-month DAILY.* window everything else on this tab uses.

Worth knowing

If the monthly summary fetch itself fails (network hiccup, Firestore hiccup), the dashboard silently falls back to embedded placeholder numbers rather than showing a hard error -- so if Master ever looks "frozen" on old numbers, a hard refresh is worth trying before assuming something's wrong with the pipeline.

Gotcha

Daily data has no settlement figure of its own -- settlement only ever comes from the monthly payments file. Don't expect a "settlement today" number; the daily view is for orders/GMV/returns trend only.
