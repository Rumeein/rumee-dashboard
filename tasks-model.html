Rumee — Tasks Tab

Rules, not AI — and a one-way street to tasks

LIVE
2026-07-24

Insights and tasks are not AI-generated. They come from a deterministic rule-based function in the pipeline that fires fixed thresholds every run. The Tasks tab is purely a triage surface -- resolve an insight, update a task's status -- there's no "add task" button anywhere.

the rule engine / the tab itself ――― dashed = vision, not live
01

Fixed thresholds, not a model

generate_insights(db) runs once per pipeline run and checks every SKU against hard-coded thresholds -- return rate above 20% is critical (and gets a task), above 17% is a warning only (no task); zero stock is critical (and gets a task), low stock under 50 units is a warning only; a Flipkart listing with CTR over 3% but zero revenue gets its own "conversion problem" insight and task. Nothing here is learned or adaptive -- change the threshold, change the behavior, that's the whole mechanism.

02

Same SKU, same category, once a day

Before writing a new insight, the pipeline checks whether one already exists for that exact SKU+category combination today -- so a persistent problem doesn't spam a new card every single run; it shows up once per day until actually resolved.

03

Not every insight becomes a task

Insights and tasks are two separate collections, linked one-way when relevant (a task can carry a linked_insight_id back to whatever spawned it). Warning-level insights (return rate 17-20%, low-but-nonzero stock) are informational only -- no task gets created for those, by design.

04

The dashboard only ever triages

Resolving an insight or changing a task's status/dropdown (Pending / In Progress / Done / Deferred) is the entire write surface here -- there is no manual "add task" button anywhere. An insight left unresolved keeps incrementing an email_count escalation counter until it hits 3, at which point the dashboard shows "Email stopped -- resolve to clear."

Not yet built

The Deep Dive vision describes marking a task "done" as the trigger for an experiment-monitoring loop (a future rumee_experiments collection: suggest → wait → evaluate → outcome). That collection doesn't exist anywhere in the codebase today -- marking a task done currently just records a timestamp and does nothing else. Worth knowing so this isn't mistaken for a bug when nothing happens after "Done."
